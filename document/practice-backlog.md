# Nest Admin 练习清单

这份清单来自一次只读代码走查，按优先级挑选真实且适合练习的改进项。建议每个任务单独建分支、补测试并独立提交。

## P0：Todo 数据隔离与资源归属

### 现状

- Todo 创建时没有绑定当前登录用户。
- 列表、详情、修改和删除没有按 `user_id` 限制数据范围。
- 通用 `ResourceGuard` 批量校验时，只要查询到一条属于当前用户的记录就会通过。

### 目标

1. 创建 Todo 时从认证上下文取得当前用户 ID 并写入 `user_id`。
2. 非管理员只能查询、修改和删除自己的 Todo；管理员保留全量访问权限。
3. 为 `todo.user_id` 增加非空约束和索引。
4. 批量资源校验需保证「去重后的请求 ID 数」等于「查询到的归属记录数」。

### 验收标准

- 用户 A 无法读取、更新或删除用户 B 的 Todo。
- 混合提交自己的 ID 与他人的 ID 时，整个请求被拒绝。
- Todo 列表不会出现其他用户的数据。
- 至少覆盖创建、列表、跨用户读取、跨用户更新和批量校验五类测试。

## P1：权限语义与缓存回退

### 现状

- `@Perm(['a', 'b'])` 的注释表示「拥有任意一个权限即可」，实现却使用了 `every`，要求拥有全部权限。
- 权限缓存未命中时返回空数组，调用处的 `??` 不会回退到数据库查询。

### 目标

1. 明确数组权限的语义：任一权限或全部权限。
2. 如果两种语义都需要，增加 `@AnyPerm()` 和 `@AllPerm()`，避免靠注释猜测。
3. 缓存未命中时从数据库读取权限，并回填缓存。

### 验收标准

- 单权限、任一权限、全部权限和无权限均有 Guard 单测。
- Redis 中没有权限缓存时，合法用户不会被错误拒绝。

## P1：补全 Refresh Token 登录链路

### 现状

服务层会生成 refresh token，但登录接口只返回 access token，控制器也没有刷新接口。

### 目标

1. 登录接口返回 access token、refresh token 与过期时间。
2. 新增 `POST /auth/refresh`。
3. 每次刷新轮换 refresh token，并使旧 token 立即失效。
4. 登出、改密和禁用账号后，已有 refresh token 均不可再用。

### 验收标准

- 有效 refresh token 能获得新 token 对。
- 已使用、过期、伪造、登出后的 refresh token 都返回统一认证失败。
- 并发刷新同一 token 时，最多一个请求成功。

## P1：升级密码哈希

### 现状

密码使用 `MD5(password + salt)` 保存。MD5 计算过快，不适合密码哈希。

### 目标

1. 新密码改用 Argon2 或 bcrypt。
2. 保留旧 MD5 校验逻辑用于兼容存量用户。
3. 存量用户首次成功登录后，自动升级为新算法哈希。
4. 统一注册、管理员重置密码、用户修改密码三条写入路径。

### 验收标准

- 新注册用户不再保存 MD5 哈希。
- 旧用户仍可登录，并会在首次成功登录后完成升级。
- 错误密码不会触发哈希升级。

## P2：CORS 配置白名单

### 现状

当前同时配置 `origin: '*'` 和 `credentials: true`，浏览器不会接受这种带凭证的跨域响应。

### 目标

1. 通过环境变量配置允许来源列表。
2. 开发环境允许本地前端地址；生产环境只允许显式白名单。
3. 对未知 Origin 不返回 CORS 许可响应。

### 验收标准

- 白名单来源可完成预检和带认证请求。
- 非白名单来源无法获得 CORS 许可头。

## P2：让幂等能力真正可用

### 现状

已有幂等拦截器和装饰器，但没有业务接口实际使用；当前「先 GET 再 SET」也不能抵抗并发重复请求。

### 目标

1. 用 Redis 原子 `SET key value NX EX` 抢占幂等锁。
2. 幂等键应包含当前用户 ID、请求路径和客户端幂等键。
3. 为注册或创建 Todo 接口启用 `@Idempotence()`。

### 验收标准

- 并发提交相同幂等键时，只有一个请求真正执行业务逻辑。
- 业务失败时释放幂等锁，允许用户修正后重试。
- 不同用户使用相同客户端幂等键时互不影响。

当前 Jest 没有发现任何 `*.spec.ts` 测试文件。

### 最小目标

2. 为 Todo、RBAC、Refresh Token 各新增一组测试。
